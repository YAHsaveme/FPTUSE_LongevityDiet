# ADR-005 — Worker-owned event ingestion, Admin Ops and reminder dispatcher (12 November 2026)

## Implemented optional target slice
- `LongevityDiet.Worker.Ops`: standalone .NET 9 REST service at private `:8086` with QA host bind `127.0.0.1:18086`. It rejects any SQL catalog other than `LongevityWorkerDb`, validates JWT issuer/audience/signature/expiry, and restricts all operations endpoints to signed `Admin` role. There are **no public mutable operations**.
- Worker-owned `WorkerOpsDbContext` migrates `WorkerReceivedEvents` and `WorkerEventDeadLetters` into `LongevityWorkerDb`; no Users, Plans, Meals, Foods or Recommendation SQL tables/FKs. `GET /api/v1/admin/events` and `/dead-letter` return paginated, sanitized metadata. `/jobs` displays genuine existing WorkerDb reminder dispatch records, not fabricated completed tasks; if the reminder dispatch store is unavailable it returns 503.
- `WorkerOwnedEventConsumer` reads four internal Redis Streams (`ldc:planning-events`, `ldc:tracking-events`, `ldc:recommendation-events`, `ldc:catalog-events`). One consumer group per source, immediate same-consumer pending replay, `XAUTOCLAIM` for orphaned pending messages, validated `eventId`/versioned event name/JSON envelope, WorkerDb source+event GUID unique constraint, SQL-before-Redis ACK. Invalid envelopes persist redacted dead-letter metadata and are published to `ldc:worker-ops-dead-letter` without copying raw payload or personal data. **Receipts mean observed/validated, NOT that domain business work was executed.**
- `LongevityDiet.Worker` now supports `Worker:OwnedOnly=true`. This branch requires an explicit `ConnectionStrings:Worker` pointing to `LongevityWorkerDb` and Redis; **it never registers `LongevityDietDbContext`, weekly-report legacy repositories, or the legacy Worker background services.** It runs the existing real reminder scheduling, dedupe, `WorkerOutbox`, and `NotificationReady.v1` Redis publisher entirely on WorkerDb. The default worker mode is unchanged for compatibility.
- Two Docker opt-in overlays: `docker-compose.worker-ops.yml` and `docker-compose.worker-owned.yml`. Neither connects to `LongevityDietDb`. All databases remain on the private Docker network. Current Gateway/Web and default legacy Worker are unchanged.
- Tests: `scripts/Test-Worker-Ops-Http.mjs` independently confirms Admin/Member 401/403, four Redis streams, SQL dedupe, invalid events/DLQ, ACK, database isolation and real dispatch API using **synthetic** QA identities only. `scripts/Test-Worker-Owned-Reminder.mjs` verifies `Identity event → Redis → WorkerDb schedules → real due dispatch → Worker Outbox → Redis → ACK` and lack of main DB connection. Both must be run only in the isolated QA Docker project or ephemeral GitHub Actions runner.

## Known remaining ADR-005 requirements
1. Worker does **not yet** calculate weekly-report business results using independent Tracking read-models. Weekly reports in Current Runtime still rely on legacy cross-domain SQL and are deliberately disabled in `Worker:OwnedOnly`. This requires event-driven job contracts and a result event consumed by Tracking with idempotent persistence.
2. Event receipts in WorkerOps are an auditable inbox, not a queue of completed business work. Ops replay/redrive controls and production dead-letter procedures need RBAC, retry caps, and operational approvals before being enabled for real users.
3. Gateway's current normal Web route still targets legacy API. Safe user migration from the current shared database, atomic feature-flag cutover, rollback plan, full distributed traces and public TLS443 deployment remain unimplemented or unverified.
4. User/team review, real-data backups and authorized production/domain configuration are **not** represented by synthetic QA tests. No lecturer or medical reviewer signoff is claimed.
